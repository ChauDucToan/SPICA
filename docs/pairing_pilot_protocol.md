## Training contract

All CLIP-owned weights are frozen, including LayerNorm, visual projection, text tower, and logit scale. Only sketch/photo visual prompts and the hard text bank's loss-side path are used as configured. The trainer retains its inline `softplus(margin - positive_similarity + negative_similarity)` rank loss: it does not call `jepa_ranking_loss`, so photo-prompt gradients are not detached. There is no patch-shuffle loss, KD, mask, covariance, or new loss; the training DataLoader remains `shuffle=True`.

The pairing manifest is loaded once while constructing the training loader and is required for the new campaign. Its SHA-256, positive treatment, campaign, role, split identity, checkpoint, cache, and summary provenance must match on comparison; pairing primary and smoke runs are always from scratch and reject resume checkpoints. Primary runs require exactly `max_steps=1800` and probes through step 1800; there is no short primary bypass. The CPU gate explicitly uses `run_kind=smoke`, `device=cpu`, `max_steps=2`, probes `[0,1,2]`, and selects actual step 2; production artifacts are marked `CPU_SMOKE`, while the dedicated gate summary remains `CPU_SYNTHETIC_SMOKE_PASS`. A primary artifact is `PRIMARY_FIXED_STEP_UNCOMPARED` until an explicit A/B comparison; it is never automatically labeled matched. Both configs now reference the generated manifest `outputs/pairing_preparation_20260906_145238/sketchy_pseudo_train_pairing.json`, SHA256 `545f67663682ed5fb79397c775848b90e206579647e605cba24cb6d4dcf8104c`: 46,624 pseudo-train pairs and 8,400 canonical positives.
